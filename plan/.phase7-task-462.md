# Phase 7 Task #462 — Concrete SSI Order Reconciliation Adapter

Status: IMPLEMENTED

## Objective
Implement the provider-specific SSI reconciliation boundary for `listOpenOrders` / `getOrder` without leaking SSI SDK or credential details into TCE contracts.

## Implemented

- Added `TceSsiOrderReconciliationAdapter` implementing `TceOrderReconciliationPort`.
- Resolves the TCE account to its owning user before provider access.
- Re-validates SSI authorization and account/environment identity before every reconciliation read.
- Reuses the existing `SsiApplicationService` boundary; SSI SDK DTOs and credentials remain behind the platform adapter.
- Uses the existing SSI `getTodayOrders(accountNo)` SDK method as the concrete current-order read, filtering provider results to open/cancel-pending states.
- Normalizes SSI provider statuses through the canonical provider-neutral mapper.
- Unknown provider statuses are surfaced as `unknownProviderOrders` and never treated as open/terminal truth.
- `getOrder` returns only the requested provider order and does not synthesize missing-provider state.
- Added deterministic tests for authorization identity mismatch, malformed query, unknown provider status, status normalization and targeted lookup.

## Verification

- SDK semantics were verified against the public `@ssi.developer/ssi-sdk` 3.2.1 API reference: equity order book uses `trading.portfolio.getTodayOrders(accountNo)` and order status values include `READY`, `SENT`, `QUEUED`, `FILLED`, `PARTIAL_FILLED`, `PENDING_CANCEL`, `CANCELLED`, `REJECTED`, and `EXPIRED`.
- No persistence, lifecycle mutation, orphan/missing detection, or automatic resubmission was added in this task.

## Dependency frontier

Next dependency-safe task: local-order ↔ SSI-state reconciliation service, including missing/orphan detection and deterministic partial-fill/terminal-state convergence. Persistence and lifecycle event emission remain later tasks.

## Safety

- Account/environment mismatch fails closed before SSI reads.
- Unknown provider states fail closed to `UNKNOWN`.
- Provider credentials and SDK DTOs remain behind the SSI platform boundary.
- Unknown execution outcomes still require reconciliation before resubmission.
- CI remains informational/non-blocking; market holidays/closed sessions do not stop implementation progression.
