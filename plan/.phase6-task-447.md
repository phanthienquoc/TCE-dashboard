# Phase 6 — Task #447 — LIVE SSI Execution Adapter

Status: IMPLEMENTED

## Objective

Connect the provider-neutral TCE execution boundary to the existing SSI application service for **LIVE SUBMIT** only. Keep provider credentials, OTP values and SSI SDK details outside the TCE domain boundary.

## Implemented

- Added `TceSsiExecutionAdapter` as the concrete LIVE `TceExecutionPort` implementation.
- Enforces `LIVE` mode before any provider call.
- Re-checks the provider-neutral trading authorization boundary immediately before submission.
- Requires authorization state `READY`; `EXPIRED`, `APPROVAL_REQUIRED`, `UNAVAILABLE` and authorization failures fail closed.
- Resolves the selected TCE account to its owning user before invoking SSI.
- Maps `TceExecutionIntent` to the existing `SsiApplicationService.placeOrder` boundary using LO for a valid limit price and MTL otherwise.
- Preserves the execution `clientRequestId`.
- Maps SSI accepted/confirmed order identity and provider status into `TceExecutionResult`.
- Maps re-auth/approval responses to `APPROVAL_REQUIRED` and provider timeouts to `TIMEOUT_UNKNOWN` with reconciliation required.
- Explicitly rejects SSI CANCEL/REPLACE as `UNSUPPORTED_OPERATION` until their concrete SDK semantics are verified; no guessed provider behavior is introduced.
- Registers the adapter in `PlatformCredentialsModule` for execution-boundary wiring.

## Verification

Deterministic coverage includes:

- approved LIVE submission;
- non-LIVE rejection without provider invocation;
- non-READY authorization fail-closed behavior;
- timeout/reconciliation mapping;
- explicit CANCEL/REPLACE non-support.
